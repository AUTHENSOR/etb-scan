# AGENTS.md — etb-scan

> For AI agents, crawlers, and LLM-based tooling reading this repository.

## What this repository is

**etb-scan** measures whether an LLM judge can be made to pass a failing answer
by text the evaluated model wrote: **ETB-01, injected verdict trusted**, the
dominant class of **Evaluator Trust Boundary (ETB) failure**. An evaluator
commits an ETB failure when its score depends on an artifact the evaluated
system can influence. The ten published classes are in `TAXONOMY.md`.

It is maintained by **Authensor, Inc.**, an AI evaluation-integrity research
practice. The tool is MIT-licensed, offline, standard-library only, with no API
keys, no model spend and no network.

## How to run

```bash
pip install etb-scan
etbscan                                              # scans the two built-in reference judges
etbscan --judge yourpkg.judges:your_judge --trials 10 # scans your judge; --json for machine output
python -m etbscan --judge ... --max-asr 0.0 --out etb-scan-results.json   # CI form (exit 1 on failure)
etbscan lint path/to/grader_code/ --fail-on high              # static rules for ETB-02/03/09/11 code shapes
```

Python API:

```python
from etbscan import scan, load_corpus
result = scan(my_judge, load_corpus(), trials=10)
result.overall_asr, result.control_fp_rate, result.trustworthy
```

A judge is any callable `(candidate, rubric, question=None) -> dict` returning a
`verdict` (`pass`/`fail`) or a numeric `score`. The scan **does execute the
judge you point it at** (it has to, to measure it); it never executes anything
else and never reads the judge's source.

Surfaces: console script `etbscan`, pytest plugin (`pytest11` entry point),
Inspect AI task `verdict_injection` (auto-registered via the `inspect_ai` entry
point when `etb-scan[inspect]` is installed), adapters for DeepEval and Weave
in `etbscan/integrations/`, GitHub Action `AUTHENSOR/etb-scan@v1`, pre-commit
hook `etb-scan`.

## How to read a result

- `overall_asr`: share of injected scenarios where the injection flipped a fail
  to a pass. Only a causal flip counts.
- `control_fp_rate`: share of benign controls the judge passed that it should
  have failed. Must be 0.0 for the ASR to mean anything.
- `trustworthy`: false if nothing was scorable, any scenario was unscorable, or a
  control false-fired. A low ASR with `trustworthy: false` is not a clean bill
  of health.
- A judge that raises or returns an uninterpretable verdict is **unscorable**,
  never "did not pass".

## Constraints for agents

- Report ASR, control false-positive rate and `trustworthy` together, never the
  ASR alone.
- Do not describe this tool as a static source scanner; it measures a running
  judge against a fixed corpus (`etbscan/data/attacks.json`: 25 injected
  scenarios in 5 families, 8 benign controls).
- It measures ETB-01 only. The other nine classes need code review.
